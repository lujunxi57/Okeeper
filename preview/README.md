# Okeeper 开源版：开始设置与账号管理

当前版本提供实际的环境检测和 Codex 账号绑定管理；定时任务、额度和云端连接仍保留为交互演示，不发送模型请求。

## 启动

在仓库根目录运行：

```sh
python3 preview/server.py
```

打开 `http://127.0.0.1:18794`。首次进入显示开始页，检测运行设备的系统、架构、Codex 版本和原生 `auth.json` 登录记录。用户点击确认后，才绑定第一个账号；已有绑定时再次打开直接进入工作台。

如果通过 Tailscale 浏览器访问，检测对象是服务器，不是浏览器所在的电脑。该版本面向单用户的 localhost 或可信 Tailscale 网络，账号管理接口不适合公开到互联网。服务器仅绑定明确的本地或 Tailscale IPv4 地址。

## 账号管理

- **绑定已有登录：** 确认检测到的账号后保存独立登录副本。检测和复制现有记录不代表已经验证账号额度、模型权限或完成真实推理。
- **添加其他账号：** 通过独立 Codex app-server 的官方设备码流程登录，在官方页面输入一次性登录码，成功并核对身份后才保存。需要在 ChatGPT 安全设置中允许设备码登录。应用不读取或提交用户密码。
- **重复添加：** 相同账号不会重复出现；明确重新绑定或登录时更新保存的登录记录。
- **选择账号：** “在工作台查看”仅更新 Okeeper 当前查看的账号，不切换或重启原 Codex 后台。
- **移除账号：** 二次确认后删除 Okeeper 中的绑定和登录副本，保留原 Codex 的登录和会话。移除最后一个账号后返回开始页。
- **数据保存：** 绑定记录和登录副本存储在应用独立的 SQLite 文件中，重启后保留。文件不由网页静态目录提供，接口不返回登录令牌。删除时启用 SQLite secure_delete。

登录进程使用新建的临时 `CODEX_HOME`，在完成、取消和退出时关闭进程并清理临时目录。首个已有登录来自运行设备的原生文件；当前版本不直接导入系统钥匙串或第三方账号库。没有可读取的原生登录文件时，可以使用独立官方登录添加。

实际绑定的账号在工作台显示真实身份，尚未接入的额度显示“尚未读取”。“先看看演示”仍可使用虚构账号体验界面，与实际账号管理分开说明。

## 配置

| 配置 | 用途 |
| --- | --- |
| `OKEEPER_CODEX_BIN` | Codex 程序路径；默认从启动环境的 PATH 查找 |
| `OKEEPER_SOURCE_CODEX_HOME` | 只读检测已有登录的位置；默认采用 `CODEX_HOME` 或用户的 `.codex` |
| `OKEEPER_SETUP_STATE_DIR` | 本版本独立状态目录；默认用户目录中的 `.local/state/okeeper-open-source` |
| `--bind` / `--port` | 监听地址及端口；默认 `127.0.0.1:18794` |

配置不接受浏览器传入路径、命令或凭据。账号管理不使用旧 Linux 调度器和账号切换服务。

## 常驻部署

`deploy/systemd/okeeper-preview.service.in` 是独立服务模板。将 `@ROOT@`、`@PYTHON@`、`@CODEX_BIN@`、`@TAILSCALE_IP@` 替换成本机值后，保存为用户级 `okeeper-preview.service` 并启用。

服务现在必须运行 `preview/server.py`，仅启动静态文件服务无法检测系统或管理账号。`public/main-style.css`、图标和吉祥物沿用 main；`public/style.css` 提供开源版引导、账号管理和响应式样式。界面素材均由本地提供。

## 验证

```sh
python3 -m unittest discover -s preview/tests -p 'test_*.py' -v
```

测试使用虚构账号、隔离目录和本地协议模拟器，覆盖导入、账号变化、去重更新、选择、移除、持久化、登录完成/取消及接口边界。浏览器检查覆盖开始页、缺少 Codex、账号增删、刷新、错误恢复和 320–1280px 布局；不代表真实用户已完成官方授权。

已安装的 Codex 0.163.0 在全新隔离目录中通过 stdio 初始化和未登录状态读取；未发起真实登录、账号切换或模型调用。Windows/macOS 原机安装、系统钥匙串读取、实际额度与后台定时仍待后续实现和验收。
